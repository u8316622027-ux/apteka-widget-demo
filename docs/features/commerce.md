# Корзина и оформление заказа

В первой версии `apteka-widget-demo` были только поиск и поддержка. При добавлении
оформления проверены оба соседних проекта:

- `apps open ai`: переиспользованы домен корзины, HTTP-репозиторий, хранилища токенов,
  валидаторы контактов/адреса и их тесты. Маппер дополнен форматом production API:
  `items[].details`, `discountPrice`, `amount_mdl`.
- `apps - kokiko(open ai)`: перенесены разметка, стили, состояние и обработчики
  интерфейса. Сохранены модальная корзина, уведомления, шаги «Доставка» →
  «Адрес и время» → «Обзор и оплата», собственные выпадающие списки, карточки
  аптек, форматирование телефона, выбор времени, переходы назад и окно успеха.
  Палитра, логотип, ссылки и поддержка принадлежат Apteka. Использован контракт отправки
  `pick-up` / `target`, адреса, оплаты и заголовка Authorization. Общая переменная
  активной корзины, значения магазина/региона по умолчанию и webhook Kokiko не перенесены.

## Инструменты

Основной MCP-контракт разделён по действиям, как в Kokiko. Каждое действие имеет
отдельную схему и аннотации, чтобы чтение справочников не было объединено с отправкой заказа:

| Инструмент | Действие |
| --- | --- |
| `search_products` | Поиск товаров; сохранён исходный контракт поиска |
| `support_knowledge_search` | Поиск по справке поддержки |
| `check_cart` | Прочитать корзину без создания или обновления серверной сессии |
| `add_to_cart` | Добавить положительное количество выбранного товара |
| `update_cart_item` | Установить количество существующей позиции; ноль удаляет её |
| `clear_cart` | Очистить только текущую корзину под общей блокировкой с отправкой |
| `search_and_add_to_cart` | Найти и добавить выбранный или единственный результат с ценой |
| `open_checkout` | Открыть форму; сам инструмент не выполняет сетевых запросов |
| `get_checkout_options` | Прочитать регионы, города и аптеки самовывоза |
| `get_delivery_windows` | Прочитать окна для выбранной аптеки или региона курьера |
| `review_order` | Проверить контакты, адрес, время и итог; создать временный review |
| `submit_order` | Отправить конкретный подтверждённый review |
| `set_widget_theme` | Переключить тему: light/dark/auto |
| `set_widget_language` | Переключить язык: ru/ro |

Публичный `tools/list` содержит ровно 14 инструментов из таблицы. Загрузка виджета
вызывает только `check_cart` и не создаёт пустую серверную корзину. Сессия создаётся
при первом `add_to_cart` или успешном `search_and_add_to_cart`; дальнейшие действия
используют тот же `cart_session_id`.
При нескольких результатах `search_and_add_to_cart` возвращает `selection_required`;
товар автоматически не выбирается. Ошибка поиска возвращает `search_unavailable`,
а не ложное сообщение об отсутствии товаров.

Прежние `my_cart`, `add_to_my_cart`, `checkout_order` и `sync_cart` исключены из
MCP-discovery и сканирования: у внутренних дескрипторов `listed=false`. Серверная
обработка вызовов по этим известным именам сохранена для совместимых старых клиентов,
но после удаления из опубликованного списка ChatGPT может запретить их вызов.
Новый адаптер использует только текущие инструменты и никогда не переключается
на прежние имена — в том числе при RPC -32601, ошибке сети или отказе модерации.
Если `review_order`/`submit_order` ещё не опубликованы, оформление временно
недоступно: виджет показывает ошибку и сохраняет корзину вместо обходного вызова.

Все вызовы продолжают одну сессию. Токен Apteka остаётся на сервере. Цены и итог
берутся из корзины API. Корзина и оформление не попадают в общий кеш ответов.

`update_cart_item`, `clear_cart` и `submit_order` имеют `destructiveHint=true`:
перезапись/удаление позиций не имеет автоматического восстановления, а отправленный
заказ нельзя отменить этим инструментом. `add_to_cart` принимает только положительный
прирост количества и не удаляет позиции. `check_cart`, `get_checkout_options` и
`get_delivery_windows` имеют `readOnlyHint=true`: даже при истечении токена во время
чтения они не пересоздают корзину. `review_order` хранит временное подтверждение и
поэтому имеет `readOnlyHint=false`, но не отправляет заказ и не является destructive.
Оплата происходит при получении; данные платёжных карт инструмент не запрашивает.

`products-api.js` связывает перенесённый интерфейс с этими инструментами;
из виджета не выполняются прямые запросы к API и не передаются значения market Kokiko.
Изменения корзины отправляются последовательно; ответы устаревших операций
не заменяют новые значения. Ошибка изменения корзины вызывает сверку с сервером.
Перед обзором заказ проверяется сервером; смена оплаты обновляет review.
Пользователь выбирает самовывоз или курьера, регион, населённый пункт/сектор,
аптеку/адрес, контакты и оплату при получении: наличными или картой.

Для вызовов из виджета дескрипторы содержат `_meta.ui.visibility`,
`_meta.ui.resourceUri` и совместимые поля `openai/widgetAccessible` /
`openai/outputTemplate`: [официальная документация](https://developers.openai.com/apps-sdk/reference/).
HTML ресурса по-прежнему включает локальные CSS/JS при выдаче через MCP.
Новых frontend-зависимостей нет.

Шаблон объявлен как `ui://widget/products.html?v=kokiko-4`, чтобы после замены UI
клиент не использовал компонент со старым идентификатором. При следующих изменениях
bundle нужно менять `PRODUCTS_WIDGET_TEMPLATE` в registry. Старый URI без версии
и прежние `?v=kokiko-2`/`?v=kokiko-3` остаются совместимыми и отдают актуальную разметку.
После обновления подключения
тестировать нужно новым вызовом инструмента в новом чате.

## Отправка

Review привязан к сессии и снимку корзины и действует 15 минут. При изменении
корзины нужно повторить review. Изменение корзины и отправка используют общую
блокировку сессии. Повторный submit одного review после успеха возвращает тот же
номер. При неопределённой ошибке сети этот review не отправляется повторно:
нужно уточнить статус заказа у поддержки.

Публичные значения оплаты `cash_on_receipt` / `card_on_receipt` преобразуются
в значения API `cash` / `card` перед отправкой. Подтверждённый отказ HTTP 422
показывает названия полей, которые нужно проверить, и разрешает ручную повторную
попытку. Сырые тела ошибок, персональные данные и токены в сообщение не попадают.
Автоматических повторов нет. Сетевые ошибки, HTTP 5xx и ответ без номера заказа
сохраняют защиту от повторной отправки, потому что результат не подтверждён.

Запрос отправляется на `/api/v1/front/order/confirm-order-by-using-mobile`
с токеном той же корзины и `orderType="ai apps"`. Успех требует `id` в ответе API.

## Хранение и эксплуатация

`APTEKA_BASE_URL` задаёт API. Для токенов доступны Upstash REST
(`UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`) и необязательный Redis
(`REDIS_URL`, при установленном Python-пакете `redis`). Без этих настроек используется
память процесса; после перезапуска пользователь должен заново создать корзину.
TTL задаётся `CART_TOKEN_TTL_SECONDS` (по умолчанию семь дней).

Для временной локальной проверки установите в некоммитящийся `.env`
`APTEKA_BASE_URL=https://stage.apteka.md` и перезапустите MCP с тем же значением
в окружении процесса. Поиск, корзина, справочники доставки и отправка заказа
используют один выбранный API; токены корзин между stage и production не переносятся.
В ngrok остаётся тот же публичный адрес, если используется тот же домен.
После переключения соберите тестовую корзину заново.

Чтобы вернуть локальный сервер на production, замените значение на
`APTEKA_BASE_URL=https://api.apteka.md` и снова перезапустите MCP. Настройка
развёрнутого production-сервера задаётся отдельно, локальный `.env` на него не влияет.

Фотографии настраиваются отдельно: `APTEKA_MEDIA_BASE_URL` по умолчанию равен
`https://api.apteka.md`. Ссылки Apteka `/media/` и `/assets/images/` в результатах
поиска и корзине нормализуются на этот хост с сохранением пути и query-параметров.
Внешние CDN не переписываются. Media-домен разрешается в CSP для статических
ресурсов; API-домен в `connectDomains` определяется только `APTEKA_BASE_URL`.
Таким образом, stage-корзины и заказы не переключаются на production из-за фотографий.

Docker-образ по умолчанию использует production для API и медиа:
`APTEKA_BASE_URL=https://api.apteka.md` и `APTEKA_MEDIA_BASE_URL=https://api.apteka.md`.
Локальный `.env`, тестовые сессии и логи исключены из build context через `.dockerignore`.
После push в `dev` GitHub Actions публикует `topf3/apteka-mcp:latest` и тег полного
SHA коммита, затем запускает опубликованный образ и проверяет production-адреса.
Проверка читает конфигурацию и не отправляет заказов.

При обновлении запущенного сервиса нужно получить новый образ и пересоздать контейнер.
Переменные окружения, заданные в панели хостинга или `docker run`, имеют приоритет
над значениями образа: для production они также должны указывать на `https://api.apteka.md`.
`MCP_WIDGET_DOMAIN` задаётся публичным доменом развёрнутого MCP-сервера.

Review и защита от повторной отправки сейчас находятся в памяти одного процесса
ThreadingHTTPServer. После перезапуска нужен новый review; несколько экземпляров
требуют общего хранилища review и распределённых блокировок перед масштабированием.

## Проверка

Unit-тесты проверяют сессии, merge и удаление товаров, валютные суммы, реальные
поля API, валидацию, Authorization, изоляцию review, изменение корзины, повторный
submit и ошибку сети. Playwright проверяет модальную корзину и самовывоз на
320/768/1280 px, курьера, согласие, смену оплаты, выбор региона/сектора,
закрытие окна и списков, возврат назад, ошибки и обновления от host.

Ручная проверка API использовала отдельную корзину: добавление, чтение,
предварительный расчёт самовывоза и курьера, затем очистка. Реальный заказ не
отправлялся. Отправка проверяется на подменённом HTTP-клиенте.
